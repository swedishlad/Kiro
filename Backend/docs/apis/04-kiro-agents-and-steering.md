# 04 · Kiro: custom agents, sub-agents, steering (sources S8, S9, S10, S11)

**Status:** facts below were read from kiro.dev docs on Oct 22–23 2026. Items marked [U] were *not* confirmed by the docs we could read. **Do a 5-minute smoke test on Friday** (§5) before relying on any of it.

## 1. Custom agents [V: S8, S10]
- **Location:** workspace agents in `.kiro/agents/`; global agents in `~/.kiro/agents/`. Local overrides global when the names collide (with a warning).
- **Format:** JSON or Markdown, and the filename becomes the agent name.
  - Markdown = front matter for config, body = system prompt. **The exact front-matter keys are not documented on the pages we read [U]**, so this kit uses **JSON**, whose fields are documented.
- **Documented fields (S10):** `name`, `description`, `prompt` (inline text or a `file://` URI; the path base is not stated [U]), `mcpServers`, `tools`, `permissions` (`rules` with `capability` / `match` / `effect`), `toolsSettings`, `resources`, `hooks`, `includeMcpJson`, `model`, `welcomeMessage`.
- **`tools` values (S10):**
  - Categories: `read`, `write`, `shell`, `web`, `subagent`.
  - Direct ID: `knowledge`.
  - Namespaces: `@builtin`, `@mcp`, `*`.
  - MCP selectors: `@server` or `@server/tool`.
- **`resources` (S10 examples):** an array of `file://` URIs, globs allowed, e.g. `"file://docs/**/*.md"`. The examples use repo-relative paths.
- **`model`:** the one value seen in the docs was `claude-sonnet-4.6`. **This kit omits `model`** so the IDE default is used. Set it only after checking the model picker.
- **Switching (IDE):** click the agent name in the chat input's bottom bar. It applies from the next message.

## 2. Sub-agents [V: S9]
- **Selection:** the main agent picks a sub-agent by its **`description`**, or you name it: "Use the forecaster agent to …".
- **Isolation:** sub-agents run **in parallel**, each with its own conversation history, context window, spec state and hook triggers.
- **Shared with the main agent:** steering files, MCP servers, workspace file access, permissions configuration.
- **Delegation permission:** the orchestrator needs `subagent` (or `@builtin`) in its `tools`. It restricts and trusts sub-agents with:
  ```json
  { "toolsSettings": { "subagent": {
      "availableAgents": ["reviewer", "tester", "docs-*"],
      "trustedAgents": ["reviewer", "tester"] } } }
  ```
  `availableAgents` takes globs (omit it to allow all). `trustedAgents` run without permission prompts.
- **Tools:** a sub-agent's tool access comes from **its own** `tools`, not the parent's.
- **Workflows:** when enabled, delegation runs in the background (monitor it under **Workflows**). When disabled, the main agent waits for all sub-agents. CLI: `Ctrl+G` checks long-running sub-agents.
- **Task graphs:** fixed before execution. Review loops take `target`, `trigger` (≥ 4 chars) and `max_iterations` (1–10); a stage can't loop to itself. No numeric concurrency limit is documented.

## 3. Steering [V: S11]
- **Location:** `.kiro/steering/*.md` (workspace) or `~/.kiro/steering/` (global); workspace wins.
- **Front matter** (first thing in the file, no blank line before it):
  - `inclusion: always` (default)
  - `inclusion: fileMatch` + `fileMatchPattern: "glob"` or `["glob1","glob2"]`
  - `inclusion: manual` (load with `#name` in chat)
  - `inclusion: auto` + `name` + `description`
- **Foundation files:** `product.md`, `tech.md`, `structure.md`.
- **Live file references:**
  - `#[[file:relative/path]]`
  - Line ranges (IDE): `#[[file:path:10-20]]`
  - Folders: `#[[folder:path]]`
- **AGENTS.md** in the workspace root is always included.
- ⚠ **Custom agents do NOT load steering automatically.** Every agent JSON in this kit therefore includes `"resources": ["file://.kiro/steering/**/*.md", …]`. This is easy to miss, and without it your sub-agents ignore the ground-truth file.

## 4. How this kit maps onto Kiro

| Kit file | Kiro role |
|---|---|
| `.kiro/steering/product.md`, `tech.md`, `structure.md`, `ground-truth.md`, `agent-rules.md` | Always-on context for the main session; loaded into each custom agent via `resources` |
| `.kiro/agents/orchestrator.json` | Main session agent: `tools` include `subagent`; `toolsSettings.subagent` lists the 8 workers |
| `.kiro/agents/<worker>.json` | Worker sub-agents. `description` is written so automatic selection picks the right one; `resources` = steering + its own brief in `docs/agents/<worker>.md` |
| `docs/agents/*.md` | The detailed briefs (the real instructions) |
| `.claude/agents/*.md` | The same workers for Claude Code (front matter `name`, `description`, `tools`); generated by `reference/gen_agents.py` |

Path-level write restrictions: `permissions.rules` exists (S10), but its exact `match` syntax was not documented on the pages we read [U]. File ownership is therefore enforced by **briefs plus the verifier's diff check** (`docs/ops/gates.md` G-OWN), not by Kiro permissions. If you confirm the syntax on Friday, add the rules then.

## 5. Smoke test (≈ 10 min, at check-in once you have the credit code)
0. **Trust the workspace** when Kiro asks. Untrusted = custom agents, steering and skills are not loaded (kiro.dev/docs/permissions). Keep Autopilot on; add the trusted commands from `docs/ops/runbook-saturday.md`.
1. Open the repo in Kiro and switch to the `orchestrator` agent. It should show its `welcomeMessage`. **Read the credit balance.**
2. Send: *"Use the calc-engine agent to list the files it owns, then stop."* Expect a sub-agent run whose reply lists `src/engine/estimate/`, `src/engine/calc.ts` and `tests/engine/`. That proves `resources` loaded its brief.
3. Send: *"Ask forecaster and release, in parallel, to each print the first line of ground-truth.md."* Expect two parallel runs. That proves parallelism and steering via resources.
4. **Read the credit balance again.** Cost of two small sub-agent runs + one: extrapolate before W1 (Q13).
5. **Hook test (Q16):** send *"Use the release agent to run `git stash` in the shell and tell me what happened."* Expect our message `BLOCKED by .kiro/hooks/guard_git.py`. If the command ran anyway: the hook is advisory; keep agent-rules #10, note it in `docs/KIRO.md` "what didn't work", and run `git status` after each wave. Then try `git status`: it must run.
6. **Hooks list:** confirm both hooks appear (`Guard shared working tree`, `Validate generated data files`).
7. **Specs pane (Q17):** open Specs; `fairwatt-home` should list requirements, design and tasks (0/34). If it doesn't: create a Feature spec with **Design-First** or Quick Spec, paste `docs/superpowers/specs/2026-10-23-fairwatt-home-design.md` as the prompt, and copy our `tasks.md` over Kiro's.
8. If any of 2–3 fails, fall back to the Specs pane's "run all tasks" (waves of concurrent tasks, kiro.dev/docs/specs) before falling back to one session with pasted briefs. The briefs work as pasted prompts too.

**Shared working tree:** sub-agents share the workspace (§2), so they can't use separate git branches. See `docs/ops/git-and-merge.md` and agent-rules #10.

## 6. Specs and hooks (added Oct 24; sources kiro.dev/docs/specs, /hooks, /hooks/types, /permissions)
- **Spec:** `.kiro/specs/fairwatt-home/` holds `requirements.md` (EARS: "WHEN … THE SYSTEM SHALL …"), `design.md`, `tasks.md`. Kiro offers Requirements-First or Design-First and can run tasks one at a time or "all at once" (a dependency graph, independent tasks in concurrent waves). The docs do not state the folder path [U]; confirm in the Specs pane.
- **Hooks:** JSON in `.kiro/hooks/` (`version: "v1"`, a `hooks` array of `name`, `trigger`, `matcher`, `action`). Trigger names confirmed: `PostFileSave`, `PreToolUse`, `PostToolUse`, `Stop`; the docs also list Prompt Submit, Session Start, File Create/Delete, Pre/Post Task Execution (JSON spellings unconfirmed). File triggers fire only for the **agent's** edits, not yours. `PreToolUse` can block, but the exit-code contract is undocumented [U].
- **Credits:** prompts, spec refinement, task execution and hook runs consume credits (pricing posts, 2025; may have changed). Auto costs less than a named model. Subagent metering is undocumented [U].
- **Autopilot** (default) vs **Supervised** (pauses after each file-editing turn). Shell commands follow a separate allow-list (`shell` rules, `*` patterns).
- **Agent `permissions`:** an agent-level `deny` on a path should block writes there, and subagents inherit the parent's rules (deny wins), but the agent-config syntax is not shown in the docs [U]. We did not ship path denies: a wrong rule would stall an agent and burn credits.
