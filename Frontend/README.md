# Watt If Frontend — Massachusetts energy dashboard

A static React + TypeScript site over the backend's committed artifacts. The dashboard makes no runtime
fetches from third parties: the build bundles `Backend/data/build/*` and `Backend/data/snapshot/*`
directly, so it always shows exactly what the backend produced. That includes the Climate tab: the
backend's Climate API (`Backend/app.py`) is saved as `climate_dashboard.json`, one answer per household
scenario, so the deployed site needs no Python server (see [Climate](#climate)). The one server piece is the optional
assistant (`api/chat.ts`), which answers visitors' questions with Google Gemini from a knowledge base
built out of the same artifacts.

## Run it

```bash
cd Frontend
npm install
npm run dev        # http://localhost:5173 (also serves /api/chat)
npm test           # parity tests against the backend artifacts (node --test)
npm run build      # type-check + static build in dist/
npm run preview    # serve dist/ locally
npm run knowledge  # regenerate the assistant's knowledge base after a backend rebuild
```

The assistant needs a Gemini API key (free from [Google AI Studio](https://aistudio.google.com/apikey)):
put `GEMINI_API_KEY=...` in `Frontend/.env.local` (git-ignored) or export it before `npm run dev`.
Without one the site works and the chat panel says the assistant isn't available.

Requires Node 22+ (the tests run TypeScript directly through Node's type stripping).
`dist/` uses relative paths, so it can be served from any sub-path (GitHub Pages, S3, a file share).

## Deploy

Vercel builds this folder: `vercel.json` pins the Vite preset, `npm ci`, `npm run build` and the
`dist/` output. In the Vercel project settings, **Root Directory** must be `Frontend` and
"Include files outside the root directory in the Build Step" must stay on (the build reads
`../Backend/data`). Set **`GEMINI_API_KEY`** in the project's Environment Variables for the assistant;
Vercel serves `api/chat.ts` as a Node.js function at `/api/chat` (60 s limit in `vercel.json`). Any other
static host works the same way for the dashboard (build, then upload `dist/`), but has no assistant.

## Assistant

A chat panel on every page ("Ask Watt If") answers questions about the site's topic: basic-service
rates, whether a competitive supplier saved money, how much homes use, the regimes and forecast, towns
and load zones, and how to read the dashboard.

- **What it knows:** `server/knowledge.ts`, a Markdown knowledge base generated by
  `src/chat/knowledge.ts` from the same artifacts and parsers the pages use: headline numbers, every
  EIA month, every basic-service rate and fixed term since 2005, the savings method and examples, RECS
  bands, both regime models, the forecast, the Climate tab's scenarios, all 351 towns, sources and
  limits. It never reaches the browser bundle. After rebuilding the backend, run `npm run knowledge`;
  `npm test` fails until you do.
- **How it answers:** `api/chat.ts` sends the instructions plus the knowledge base as the system
  instruction to `gemini-flash-latest` (Google's alias for its newest Flash model) with low thinking,
  and streams the reply to the browser as NDJSON. The knowledge base comes first and never changes
  between visitors, so Gemini's implicit caching can reuse it; today's date and the visitor's current tab
  go last. Answers Gemini stops for safety or recitation are replaced with a polite decline. Change the
  model or thinking level at the top of the file; pin a versioned model name to freeze behaviour.
- **Free tier:** works with a free AI Studio key, within Google's per-minute and per-day quotas (see
  the key's limits in AI Studio). Every question sends the whole knowledge base (roughly 20–30K tokens),
  so the tokens-per-minute quota is usually what runs out first; visitors then see "busy, try again in a
  minute". Turning on billing for the key raises the quotas.
- **Guards:** messages up to 2,000 characters, the latest 24 turns, max 8,000 output tokens, and
  20 requests per IP per 10 minutes per function instance. That limiter protects the quota, not a
  security boundary; for a public launch add a Vercel Firewall rate-limit rule on `/api/chat`.
- **Privacy:** questions go to Google's Gemini API. On the free tier Google may use prompts and answers
  to improve its products (including human review), so the panel says so and asks visitors not to share
  account details; a paid key doesn't have that use. The conversation is kept in `sessionStorage` only,
  and the function logs token counts, never message text.
- **UI:** `src/chat/Chat.tsx`; replies are rendered by `src/chat/markdown.ts`, which builds React
  elements (no HTML injection) and only links to in-site `#/` routes, `http(s)` and `mailto`.

## Staying in sync with the backend

Where the frontend computes something the backend also computes, it ports the backend's code and
`src/data/data.test.ts` pins the result to the committed artifact:

- savings calculator (`src/data/savings.ts`) reproduces every example in `savings_model.json` to the
  last bit, including Python 3.12+'s compensated `sum()` and half-up cent rounding;
- basic-service term lookup matches `savings_model.py` for every utility and month;
- weighted percentiles reproduce `consumption_stats.json` and the map thresholds;
- the typical-account vector matches `consumption_stats.json` (12-month trailing account mean);
- `regimes.json` and `mc_forecast.json` are checked for the fields and invariants the pages read;
- `climate_dashboard.json` must hold one API answer for every scenario the Climate tab offers, with the
  fields and invariants the tab reads (`src/data/climate.test.ts`);
- the assistant's `server/knowledge.ts` must equal what `src/chat/knowledge.ts` builds from the current
  artifacts (`src/chat/knowledge.test.ts`).

Regenerate the backend artifacts and run `npm test`; a failing test means the two have drifted.

## Layout

```
api/           chat.ts: the assistant's serverless function (POST /api/chat)
server/        knowledge.ts: the assistant's knowledge base (generated; do not edit)
scripts/       knowledge.ts: regenerates server/knowledge.ts (npm run knowledge)
src/
  data/        parsers, backend ports and their tests (pure, no DOM)
  chat/        assistant panel, knowledge-base builder, Markdown reader and their tests
  components/  SVG charts (line, column, stacked, range, scatter, histogram, map) and UI pieces
  sections/    one file per tab; all but Overview are lazy-loaded
  geo/         351-town TopoJSON (MassGIS boundaries via LMEC, simplified to 6%)
```

## Climate

The Climate tab shows the backend's Climate API (`POST /api/climate/dashboard`, `Backend/backend/climate/`).

- **Static (default, what Vercel serves):** `python3 -m backend.climate.build` (in `Backend/`) sends the
  endpoint one request per household scenario (5 monthly amounts × 3 flexible-use levels × battery or not)
  through the FastAPI app in process and saves the answers to `Backend/data/build/climate_dashboard.json`;
  the tab picks the saved answer for the visitor's choice. Rebuild it after changing the climate backend,
  then run `npm run knowledge` and `npm test`.
- **Live (optional):** run the API (`cd Backend && uvicorn app:app --port 8000`) and build or run the site
  with `VITE_CLIMATE_API_URL=http://localhost:8000`. The tab then asks the API for every choice, adds a box
  for any monthly kWh, and shows "Live from the Climate API". If the API can't be reached it falls back to
  the saved answers. The API allows any origin (CORS), so a deployed site can point at a hosted API too.
- Types mirror the API's Pydantic models (`src/data/model.ts` ↔ `Backend/backend/climate/schemas.py`,
  `Backend/contracts/climate_dashboard.schema.json`); helpers are in `src/data/climate.ts`.

## Bill reader (OCR)

- `npm run dev` and `npm run build` first run `scripts/copy-ocr-assets.mjs`, which copies the
  Tesseract.js worker, its WebAssembly core and the English model from `node_modules` into
  `public/ocr/` (git-ignored). The page loads them from this site only, so no CDN is contacted and
  the bill photo never leaves the browser. About 7 MB is downloaded once, only on the Bill check tab.
- `src/data/bill.ts` turns bill text into fields (utility, kWh, total, supply rate, billing period),
  keeping the line each came from; `src/data/billCompare.ts` does the comparison and picks the
  suggestions. Both are pure and covered by `src/data/bill.test.ts`.
- Usage and price are only published statewide, so the comparison is with the typical Massachusetts
  account and the bill's own utility's basic-service rate, and the page says so.

## Design notes

- Apple-style system UI: grouped grey page, white rounded cards, system colours, flat fills. No
  gradients, no borders on cards, and shadows only on things that float (tooltips).
- Colours are CSS custom properties with separate light and dark sets (`src/styles.css`).
- Type: the system font stack (San Francisco on Apple devices, Segoe UI on Windows), so no web
  fonts are downloaded.
  Regimes always pair colour with a shape (▼ ● ▲) and a word: Low / Mid / High for the level model
  (`hmm_regimes.json`), Below / Within / Above range for the usual-range model (`regimes.json`).
- Every chart has a Table view, keyboard reading (arrow keys) where it is a time series, and a
  hover tooltip; nothing is reachable only by hovering.
- Towns are never coloured by consumption: there is no verified per-town usage source, and the
  backend's map artifact says so.
